Priority decisions

Priority is scored on the subject, not on a sentence: a request is not urgent because of its wording but because its deadline has passed and later messages are still chasing it. Every item extracted from a subject inherits that subject's band. Click a row for the arithmetic.

Related-message groups

Messages are grouped by subject identity, not by shared words. Two subjects that overlap only on a cheap word — “review the privacy checklist” and “review the model results” — stay apart. Click a group for its timeline, deadline history and recorded contradictions.

Ask the assistant

Questions are routed to an intent first and answered from the ledger where one applies; retrieval handles the rest and runs alongside every answer so a relevance score is always shown. If the evidence does not support an answer, it says so instead of composing one.

Privacy-aware routing

Every message is routed at ingest. Blocked messages are never added to the search index, so no query can rank one — the exclusion is structural rather than a filter applied to results. send_to_external_service is denied for every message including harmless ones, because this package contains no network client at all.

Baseline against optimised, measured live

The optimised component is the retrieval index. v1 scores TF-IDF cosine against every document; v2 generates candidates from a pruned inverted index, reranks the top ones exactly, and falls back to int8 latent embeddings only when lexical scoring cannot fill the result set. Both are built here, in this process, over the corpus you loaded.
